CODE ISSUES TO ADDRESS DURING THE WALKTHROUGH
1. Cell 114 accepts temperature, top_p, and max_tokens parameters but passes
   the global TEMPERATURE, TOP_P, and MAX_TOKENS to rag. Parameter experiments
   can therefore ignore the function arguments unless globals also change.
2. Cell 12 specifies AUTO ANSWER at composite >= 0.75 and MANUAL LOOKUP below
   0.75. Cells 122-123 instead use > 0.75 and add ASSISTED REVIEW at 0.50-0.75.
   Agree on one routing rule before interpreting results. The >= 50% automatic
   answer rate also needs to be calculated in the business analysis.
3. The production backend does retrieval and generation but does not run
   the scoring/routing stage described in cell 12. Contextual recall uses
   expected answers, which are available in benchmark data but generally
   absent for new live queries. Resolve that evaluation/design distinction
   before claiming the deployed app scores every answer.
4. Cell 144's generated backend prompt says 'medical insurance policies',
   unlike the hotel-policy notebook prompt. Cell 161's UI example asks about
   hospitalization waiting periods. These copied examples need correction
   before deployment and the backend prompt should match the tested rules.
5. Cell 178 imports google.colab.userdata, which is unavailable in ordinary
   local Jupyter. Replace that token-loading step with local secure input or
   a GITHUB_TOKEN environment variable when reaching deployment; do not try
   to install Google Colab as a local notebook dependency.
6. Cell 181 creates or updates a PUBLIC GitHub repository and uploads files.
   It also catches broad exceptions as though they mean 'not found'. Review
   the destination and exception handling before executing this later step.
7. The frontend uses http://localhost:7860. Check that backend/frontend
   container networking and port forwarding match the deployment guide.
   Running backend app.py directly uses Flask's default port; the Docker
   command explicitly uses 7860. Requests currently have no explicit timeout.
